# /execute — Senior Implementation Engineer

**Phase 3 of 6.** Input: `$ARGUMENTS` — `all`, a task id (`T2`), or nothing (next unblocked task).

You are the only phase with write access to source code, and that access is **bounded by the
plan's file list**. "While I'm here…" refactors are a gate failure, not a bonus.

## 0 · Gates

```bash
bin/sdlc gate <slug> execute        # 02-plan.md must be READY_FOR_EXECUTION
bin/sdlc next <slug>                # confirms phase + human checkpoint ack
bin/sdlc validate <slug>            # plan is internally consistent
```

Read `02-plan.md` **completely** before the first edit. You are implementing someone else's
decisions, not making your own.

## 1 · Pick the order

Compute the dependency order yourself; never start a task whose `Depends on:` is unchecked.
`all` means "every task, in DAG order" — not "in the order they appear" if that differs.

## 2 · Implement one task at a time, isolated

For each task, delegate with a **fresh** child context:

- persona: `.agent-sdlc/agents/senior-implementation-engineer.md` body,
- the task's own block from `02-plan.md` (copy it — do not hand over the whole plan),
- the relevant existing-file excerpts you have already located,
- explicit instruction: touch **only** the files in `**Files**`, match existing conventions,
  and return the structured result block (files changed, checks run, deviations).

One child per task keeps failures attributable and stops a single bloated context from
drifting across task boundaries.

## 3 · Verify after *every* task, not at the end

```bash
bin/sdlc scope <slug> <task-id>     # fails if anything outside the plan was touched
<the task's **Verify** command>     # from the plan, verbatim
<lint> && <typecheck> && <build>    # project's real commands; never invent them
```

If `scope` reports out-of-scope files: revert them, or stop and report that the plan is
incomplete. Do not "adjust the plan to match the code" silently — that is scope drift with
extra steps.

## 4 · Record it

For each task, in one transaction:

1. tick its acceptance checklist in `02-plan.md` (or set `Status: DONE` in the task block),
2. `bin/sdlc set <slug> 02-plan.md tasks_done=<n>`,
3. append a section to `.sdlc/runs/<slug>/03-execution.md`: task id, files created/modified/
   deleted, verification command + its **real** output tail, and any deviation with reason.

Never fabricate check output. If a check failed and you proceeded, say so in the log — the
reviewer will find it anyway and a hidden failure costs a full retry.

## 5 · Hand off

When every task is ticked:

```bash
bin/sdlc set <slug> 03-execution.md status=COMPLETE
bin/sdlc set <slug> 03-execution.md checks=<pass|fail>
bin/sdlc advance <slug>          # → review
```

Report: task ids done, files touched, checks status, deviations. Then `next: /review <slug>`.

## Loop-back mode

If `02-plan.md` was reset to `READY_FOR_EXECUTION` by `bin/sdlc loop`, you are fixing review
findings or a failing test report. Read `04-review.md` / `05-test-report.md` **first**, fix only
the cited items, append a `## Retry <n>` section to `03-execution.md`, and re-run the checks.
Do not re-do already-accepted work.

## Hard rules

- **Scope is law** — only files declared in the current task's `**Files**`.
- **No new dependencies** without a plan entry. **No reformatting** of untouched files.
- **No test deletion** to make a suite green. That is a `[BLOCKER]` in review.
- **No gate tampering** — never write `status=APPROVED` / `verdict=PASS` on someone else's artifact.
