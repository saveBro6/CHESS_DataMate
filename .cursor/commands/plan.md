# /plan — Tech Lead & Task Planner

**Phase 2 of 6.** Input: `$ARGUMENTS` — a path to `01-spec.md`, a slug, or nothing (infer the
single active run).

Break an approved spec into **atomic, dependency-ordered, individually verifiable** tasks.

## 0 · The gate is not negotiable

```bash
bin/sdlc gate <slug> plan     # exits 1 unless 01-spec.md → status: APPROVED
```

If it blocks, stop. Print the reason and the remedy — `bin/sdlc approve <slug> spec` — and end
the turn. **Never** write a plan against a `DRAFT` spec, and never flip the spec to `APPROVED`
to unblock yourself. A blocked gate is the system working.

## 1 · Read, then delegate

Read the approved spec yourself (it is short and it is the contract), plus just enough of the
codebase to anchor file paths. Then delegate the DAG construction: pass
`.agent-sdlc/agents/tech-lead-planner.md` body + the spec body + the real file inventory you
found to the `subagent` tool. The child proposes; you validate and write the artifact.

## 2 · Shape of a valid task

Your only output is `.sdlc/runs/<slug>/02-plan.md`, written from the template. Every task is a
`### T<n> — <title>` heading containing, without exception:

| Field | Rule |
|---|---|
| `**Depends on:**` | `T<k>` list, or `none`. The graph must be a DAG — no cycles, no forward refs |
| `**Files**` | `- create:` / `- modify:` / `- delete:` with exact repo-relative paths in backticks |
| `**Interfaces**` | The signatures/schemas this task introduces or consumes — before implementation |
| `**Acceptance criteria**` | Testable statements, not adjectives ("returns 429 after 5 calls in 1s") |
| `**Verify**` | A command that proves it (`npm test -- limit`), runnable as written |

Rules that keep the pipeline honest:

- **Atomic** — one task should be reviewable in isolation and revertible on its own.
- **File scope is a contract** — `/execute` and `bin/sdlc scope` enforce exactly these paths.
  If a file is not listed here, the engineer may not touch it.
- **Contract-first** — define interfaces in the task that owns them, before consumers.
- **Totality** — every acceptance criterion in `01-spec.md` maps to at least one task. Append a
  traceability table (`AC → task`) at the end of the plan.
- **No silent scope** — work discovered mid-planning that the spec does not cover goes to
  *Deferred*, not into a task.

## 3 · Close out the plan

```bash
bin/sdlc set <slug> 02-plan.md tasks_total=<n>
bin/sdlc snapshot <slug>     # non-git projects only: baseline for scope audits
bin/sdlc validate <slug>     # catches DAG/accounting drift before execution
```

Frontmatter `status: READY_FOR_EXECUTION` must be set, and `tasks_done: 0`.

## 4 · Hand off

Report: task count, the critical path, files touched, and the human checkpoint:

```
next: bin/sdlc ack <slug>   (human reviews the plan)   →   /execute <slug> all
```

## Hard rules

- **Read-only on source.** Only `.sdlc/**` is writable. You plan; you do not implement.
- **Do not re-litigate the spec.** If the approved approach is wrong, say so explicitly and
  stop — the remedy is a spec revision, not a creative plan.
- **No task without a verify command.** "Looks correct" is not a gate.
